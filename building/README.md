# 灰燈寨 · 全劇場景模型與上部配置編輯器

## 全劇模型（2026-10-06）

目前採雙棟配置：A 棟舊住商樓最高 26F，B 棟後勤管制樓最高 50F，共用地下基座。正式棟別由製作規格讀入 `scene-flow.json`，不由 3D 自行猜測。15F、22F、26F 三組橋在同層跨棟，26F 的四個條件分道仍各有門端。B 棟 L1（29／30／31F）與 L2（47／48F）以垂直井道、拉閘及車廂鏡位表示；30F 平台保留原探路。模型中的車廂標記是各段構圖位置，不代表同井有多部車，也不是已實作的遊戲電梯。

`index.html` 為目前關卡流程的全劇 3D 查閱模型，從 B3 到 50F。48 個流程節點全部可選取，72 個次場景以原圖號定位在所屬路線；56 條動線的方向、門檻、回訪規則及圖像順序直接沿用 `scene_graph.json`／`scene-flow.json`。

樓層參考框採低不透明度虛線，與實體移動路線區分。左側「樓層線框」可獨立隱藏雙棟樓層參考框及其標籤，不隱藏場景、移動路線或右側樓層資訊。預設顯示，切換範圍、樓層或樓高時保留當次勾選狀態。

- 45 個固定空間與 M1 維修脊柱共 46 個空間節點，包含 43F／44F 深層檔案、44F → 45F 七窗夾道，45F 展示、46F 生活工場、47F 交易簽核、48F 冷藏、49F 水箱運送與 50F 核心。U2b／U4b／U6b 分別是 46F／48F／49F 的局部下凹夾層。
- 51 條實體路線具有連續幾何；R32、U4 的原場景回返及 3 條結局演出連線只列演出資訊，不畫實體通道。R33／POST 不另造房間，肉身回返不畫成 50F 到 B3 的樓梯。
- 3F–7F、9F–10F、12F–14F、16F–22F、24F–26F、28F–30F、33F–36F 探路次場景逐層配置；一般接景、分岔、回程捷徑均有對應圖號，可直接開啟劇本、製作規格與圖像製作單。
- 可依章節、單一樓層或目前路線檢視，也可搜尋節點、切換壓縮／等距樓層及正面／俯視／立體角度。路段清單依主場景 → 次場景 → 下一場景排列，回程沿原圖號反向排序。
- 模型標籤遠看顯示編號，拉近依實際畫面比例顯示中文場景名稱，主場景與過渡次場景皆適用；選取、滑鼠指向或鍵盤聚焦也可展開。名稱讀取正式流程資料，可用「場景名稱」開關關閉；擁擠處先退回編號，避免遮住其他標籤。
- 正式樓層與拓撲已同步；尺寸、方位、局部高差及家具只是空間灰盒提案，不是已驗收的建築圖、遊戲鏡位或正式美術。

本頁是查閱模式，不載入、不修改原編輯器的本機配置。既有編輯功能移至同目錄 `editor.html`，仍使用相同來源與原儲存鍵；舊自訂 R23 等房間不會與新增的正式下部場景混用。全劇下部配置目前不提供編輯／存檔。

### 場景內容標示

左側「內容標示」包含道具／線索、解謎／操作、事件、恐怖點、BOSS 五個獨立開關。遠看收起內容，拉近先顯示分類圖示，再依空間展開名稱；與場景標籤共用防重疊排版。右側「場景重點」保留所選節點的分類清單，點選可定位並查看原文、圖號、條件與製作要求，也可透過網址中的 `marker` 分享同一項目。編號開關與內容標示互相獨立。

標示涵蓋主場景及有操作或近看圖的次場景，逐層探路直接沿用正式流程的辨路、操作與復原條件；拉閘門電梯另標既有倒影與假停靠恐怖點。道具／線索分類不代表全部可以拾取；BOSS 僅對應阿尋、阿彪、小花，UD-01／UD-02 與其他怨靈仍依原遭遇歸類。非實體結局僅列右側資訊，不新增房間；M1 跨層標示僅在完整路段顯示，不在樓層切片猜測七窗的精確位置。

所有點位都是場景內位置示意，包含非同時發生的事件，不模擬遊戲進度、解鎖或實際互動熱區，也未增加道具的正式 3D 美術。內容來源為 `building/marker-definitions.js` 的重點索引與正式圖像表；`tools/build-model-markers.mjs` 驗證圖號、所屬節點及原文錨點，產生 `building/scene-markers.json`，每次模型建置自動更新。`node tools/build-model-markers.mjs --check` 檢查是否過期；`node --test building/model-markers.test.mjs` 與 `reviews/verify-model-markers.cjs` 驗證資料及介面。

`current-spatial.js` 管理全劇灰盒幾何，直接從正式流程讀取樓層及連線；`current-props.js` 補充下部場景地標；`current-model.js`／`current-template.html` 管理全劇查閱。`npm run build` 同時產生 `index.html` 與 `editor.html`，包含 Three.js 與資料，不依賴外部 CDN。全流程單元驗證：`node current-spatial.test.mjs`；瀏覽器驗證：根目錄 `reviews/verify-current-model.cjs`。

## 上部配置編輯器（原第二十七版）

`editor.html` 是保留使用者舊存檔的配置沙盒，未把舊座標自動搬成雙棟。其預設幾何與樓梯工具不代表目前正式跨棟／電梯配置；現行完整空間請以 `index.html` 為準。以下保留沙盒操作說明，不作正式路線規格。

以下操作說明適用於 `editor.html`，保留原有 26 個上部節點與編輯格式。

開啟頁面時預設關閉編輯模式，以全棟 3D 斜視角查看模型。左上「編輯模式」開關統一控制房間、道路與樓梯編輯；開啟後，畫面底部提供目前選取物件、「復原／重做／完成」。左側保留樓層、建築外框與顯示控制，方便找到要修改的位置。

左上「編輯模式」開關可隨時開啟或關閉編輯。關閉會隱藏移動軸與編輯點，停止尚未完成的拖曳；此時只能查看房間、旋轉、平移和縮放視角，點樓梯也不會自動進入編輯。重新開啟會保留目前視角和樓層。進入樓梯連接工具也會開啟編輯模式，原按鈕會變成「返回物件編輯」；按下可回到一般 3D 操作，保留目前樓層與視角並取消尚未完成的連接。按「完成」或關閉開關則結束編輯。

- 房間：點房間本體或編號只選取，不會因拖動房體而改變位置。選取後，拖 X／Y／Z 彩色箭頭或平面把手移動。「上一層／下一層」變更房間的樓層，B1 上一層是 1F。
- 新走廊：選房間後，拖牆面上的青色「＋」到另一個房間；目標房間亮起後放開，即建立走廊。同層連走廊，可見的不同樓層房間自動接樓梯。
- 現有走廊：點選通路後，拖 A／B 到其他房間即可改接；拖金色節點可改變轉折。
- 樓梯：直接拖曳模型中的樓梯，調整命中梯段的位置。選取後只顯示該樓層區間的樓梯；其他樓層的梯段與預覽會隱藏，視角保持不變。
- 空白處拖曳旋轉視角、右鍵平移、滾輪縮放。放開物件才保存這次移動；Esc 取消尚未完成的拖曳，完成後仍可復原或重做。
- 「完成」：結束物件編輯，保留目前視角與配置。
- 「連接樓梯 A → B」：在模型畫面依序點選起點與終點，切換目標樓層時保留 A 點；再按同一位置的「返回物件編輯」，即可繼續編輯房間、道路與樓梯。

點選模型中的房間本體或編號，右側會顯示房間編號、名稱、樓層、關卡目標、故事空間說明與入口／出口。一般檢視、3D 編輯、A → B 連接、樓梯與進階編輯都保留完整房間資訊，包含原文依據、上一間／下一間與入口／出口；切換房間時資訊欄回到頂部。連接工具的設定放在資訊下方，不會取代或打斷房間說明。編輯中使用右側的房間選單或上一間／下一間，移動軸會同步到所選房間。

## 六段故事通路與十二個鏡位

舊沙盒依其原幾何配置可查看通路；鏡位文字讀取 scene-flow.json，但不據此把舊樓梯改造成跨棟橋或電梯。左側「通路檢視」可選擇路線、查看全段或定位各鏡位；「返回全棟」、切換房間／樓層或開啟編輯即可離開。現行 33 個操作次場景及其餘過渡的正式空間對照請使用全劇模型；兩者均不是已交付的第一人稱遊戲場景。

- 後廚碗架、紅扶手、住宅封門、洗衣槽與排水槽、橋頭窗框、診所後簾、貨梯內壁、卸貨護角及吸音板均為簡化灰盒。
- 跨幕梯段增加水平接入及側向平台，避開上方折返梯；每個探路樓層各有水平平台及換側短梯；封毀舊梯只作不可行方向的地標。
- 初始故事圖仍為 26 個節點、30 條連線；門檻、方向及上下部邊界不變。R24↔R25 屬下部，未加入本模型。
- 通路造景可關閉；單層檢視只顯示該層的造景。編輯模式暫時隱藏造景，保留原有房間、走廊、樓梯操作。
- 通路造景與鏡位從目前連線推算，移動房間或調整道路後會重新定位；刪除或改接至其他房間的通路不再套用原故事造景。自訂配置仍需人工核對空間與鏡位。
- 沿用原場景 JSON 格式，不改寫使用者存檔；匯入／匯出、復原／重做照常。瀏覽通路不寫入遊戲進度或修改配置。

修改 `transition-spaces.js` 或模型原始碼後執行 `npm run build`。幾何與舊配置保護檢查：`node --test transition-spaces.test.mjs`；瀏覽器檢查腳本為 `reviews/verify-transition-model.cjs`。

## 直接拉走廊

開啟編輯模式，點選起點房間，牆面會出現四個青色「＋」。按住其中一個拖到目標房間，亮起預覽後放開即可建立，保留目前視角。若要換掉現有走廊的接入房間，先點走廊，再拖它的 A 或 B 到新房間。

只有拖到有效房間並放開才保存；放在空白處或按 Esc 會取消。完成後可復原／重做，新增及改接的走廊也會包含在場景匯出檔。

## 新增房間

1. 開啟左上「編輯模式」，用「單層檢視」選擇要建造的樓層。
2. 按「＋ 新增房間」，在模型地面按住左鍵拖出矩形；放開即建立。
3. 新房間自動編為 R23、R24…，標示「自訂房間」。建立後可直接用彩色軸移動，或使用連接工具接到其他房間。

若原本查看全棟，會以目前選取房間所在的樓層建造。拖曳時顯示樓層與長寬；至少 3 × 3、最多 60 × 60，位置吸附 0.5 格。按 Esc 或「取消新增」可取消，復原可撤回已完成的建立。切換樓層或關閉編輯時，尚未完成的房間不會保存。

新房間、自訂名稱、位置、尺寸、樓層與連接會一起保存，並包含在整棟場景匯出檔內。原故事房間與原文連結繼續保留。

壓縮概覽的樓層高度以初始建築為固定基準，移動房間不會讓整棟突然縮高或下沉。需要在原本空置的樓層配置房間時，可切換「等距樓層」查看完整樓高。

使用 Chrome、Edge 等支援 WebGL 的瀏覽器開啟 `editor.html`。Three.js 與資料已內嵌，可以離線使用。

左側上方「場景檔案」可隨時匯出或載入，不必先進入編輯。按「匯出場景檔」保存目前已完成的配置；日後開啟 `editor.html`，按「載入場景檔」選取備份，就能接著編輯。

左側樓層索引與目前房間配置同步；按鈕顯示單一樓層時，直接選取該層。例如按「B3」只顯示 B3 房間、通道及通往 B2 的梯段，不顯示 1F 樓梯。「全棟概覽」可恢復整棟顯示；自訂移動房間後，區域的樓層範圍也會同步更新。

在一般檢視模式切換「單層檢視」，就會自動顯示途經該層、銜接上下樓層的梯段，不需要先點選樓梯或進入編輯。地下 B3、B2、B1，以及沒有配置房間的空樓層也能直接查看。

按「連接樓梯 A → B」直接進入模型上的兩點連接模式。完成一次拖曳或連線就會保存。需要其他形狀或精確數值時，可由連接工具右側展開「進階設定」。

從 B3 到 43F 的每一層樓梯都能在模型中查看，包含途中沒有房間的樓層。直接拖曳樓梯可調整命中梯段的位置，保留房間門口端點與其他梯段。移動後，自動銜接走道造成的同層回圈與重疊折返會消除；拖曳預覽、保存後與載入舊場景都使用相同結果，保留既有樓梯位置與跨層折返梯，只清理包含自動補接段的同高度繞路，不重設保存資料。

初始配置沿用原圖的 26 個節點與 30 條連線。沙盒允許改變連線關係；編輯後的道路、樓梯與落層屬於自己的設計草稿，原文規格仍可作為參考。

## 故事空間修正

以下為隨附的初始配置理由。自行編輯後，房間的實際位置可能不同；自訂落層不代表原文指定樓層。

- 地下 P0、P1、P2 以短管線通道相接；P2 處理室正式定位在 B3，出口爬梯經 B2、B1 至 1F。
- R1 櫃檯後是 R2 舊麵店後廚，紅鐵梯從後廚梯口直接上接 R3 側門，不繞建築外緣或返回 R1。R3 宿舍與 R4 洗衣廁所在 2F，R5 工坊改置 8F，沿 3F–7F 側路相連；R4b 是 R4 內的梯下神壇，不另造房間。
- R6 在 11F，循 12F–14F 側路抵達 15F 的 R7–R11 產線。R7 窄橋接 R8；R9 比 R8 低兩級，R10 是祈禱平台，R11 為錯層第三排工位。沒有新增 R7→R11 或 R8→R11 直連。
- R12–R16 構成修理、診療、貨梯與設備後勤群。R15 機房與 R16 伺服器室貼鄰，以短梯／防火門銜接，再從冷卻管下的維修夾層上行至 R17。
- R18 改為狹長消音走廊。R19 與 R20 共用同一片實體單向玻璃，由側門繞至墊高的觀察側，再往 R21。R22 保留釋放平台、下折避梁與向 43F 上行出口。
- 跨幕樓梯放在建築內的維修脊柱；R17→R14 誤導回路仍獨立保留。共用貨梯只呈現轉接井道，不新增乘梯跳層通路。

## 其他編輯工具

1. 在 3D 畫面選取房間，拖彩色軸或平面把手移動。
2. 「連接樓梯 A → B」也可依序選兩個房間門口，新增通路；跨樓層會生成樓梯。
3. 點走廊後拖金色節點調整轉折，點「＋」加入節點。一般通路的 A／B 可沿房間牆面調整路口；平台連線的 A／B 保持對原房間或樓梯平台的連接。
4. 樓梯連接工具的「拆路」可刪除連接；誤刪可立即復原。
5. 需要尺寸或其他精確數值時，按「連接樓梯 A → B」，展開右側「進階設定」，使用房間、道路與樓梯設定表單。

拖曳房間與轉折點時，平面位置吸附到 0.5 單位格點。移動房間後，相連路口會跟著牆面移動，路線維持直角轉折。

### 在模型畫面連接 A、B 樓梯

1. 按左側「連接樓梯 A → B」。
2. 點目前樓層樓梯平台的金色「＋」，指定 A 點。
3. 使用畫面上方樓層選單或「上一層／下一層」切換到目標樓層，A 點會保留。
4. 點該層樓梯平台的金色「＋」，指定 B 點。A、B 之間自動產生樓梯並保存，不需要拉中間階梯。

若兩端上下重疊或水平距離不足，系統會自動加入折返梯段與中間平台。也可依序點選房間牆面的藍色「＋」，連接房間路口。按 Esc 取消尚未完成的連接。

可連接房間與房間、樓梯平台與房間、兩個樓梯平台，包含地下層和途中空樓層。房間與樓梯移動後，連接點會跟隨。兩個點都由你指定；平台分支會另外保存，不會更改原通路的房間端點。

要移除連接，按「拆通路」後點該條通路；可用「復原／重做」撤回。刪除樓梯時，附屬平台連線一併移除；改動樓梯涵蓋樓層使平台不再存在時，該平台的附屬連線也會移除，整次修改可復原。匯出／載入場景 JSON 會包含這些連接；較舊且未含平台連線的 JSON 仍可載入。

### 進階模式中的樓梯控制點

選取房間後，在右側「連接的樓梯」點選要調整的樓梯，也可以直接點模型中的樓梯。尚未逐層拆分時，拖曳畫面上的「✥ 移動樓梯」，可將整組梯段與中間平台一起平移；兩端房間的門口保持固定，門口到樓梯的平坦接近路段會重新銜接。

放開滑鼠即保存，按 `Esc` 可取消本次拖曳，完成後仍可復原／重做。若要改樓梯形狀，拖金色轉角；若要移動門口或改接房間，拖 A／B 端點。

### 編輯整棟主樓梯

1. 按「連接樓梯 A → B」，切換工具列的「移動」並點選主線樓梯，再在右側「主樓梯 · 選擇樓層」挑選目前要放置的梯段。選單依 **B3 → B2 → B1 → 1F → 2F → … → 43F** 排列，共 45 個相鄰樓層區間，空樓層也可選取。
2. 移動滑鼠，在目前樓層的地面上預覽位置。按 `R` 或「旋轉 90°」調整樓梯方向；尚未點下之前只是預覽。
3. 點一下地面，放置目前梯段並自動銜接上一層。完成後保存並結束放置模式；仍保留選取的梯段。要重放可按「點地面放樓梯」，要處理其他樓層則切換樓層選單。

按 `Esc` 或取消操作可退出尚未完成的放置，不寫入變更。每次放置只修改目前選取的梯段，其他樓層不會跟著平移；既有房間位置與兩端門口保持，必要的接近路段會重新銜接。完成後可立即復原／重做。

精修、放置、旋轉及拖曳時，只顯示目前選取的樓層區間，例如 B1 → 1F；切換編輯梯段會同步更新顯示。此顯示篩選不會刪除或修改其他樓層的樓梯，關閉編輯後恢復目前檢視範圍。

需要指定轉角時，展開「微調形狀」，再拖金色控制點，或按「直梯／L 形／U 形」。微調預設收起，平常選樓層、點地面即可。

此入口整理既有主線的跨層樓梯及最後的出口梯，讓整棟主樓梯可逐層編輯。樓梯編輯保留房間現有位置與用途；43F 是上部出口門檻，沒有新增 R23 房間。這些梯段位置與形狀仍是自訂空間配置，不代表故事原文指定的建築尺寸。

單段放置、拖曳與形狀修改完成後即保存，可復原／重做，也會包含在匯出的配置 JSON 中。仍可由「樓層編輯」處理房間、其他通路與分支樓梯。

### 每一層分開編輯樓梯

1. 其他跨樓層通路可先選取樓梯，再按右側「逐層設定樓梯」。途中每個樓層都會有可編輯的梯段，沒有配置房間的空樓層也包含在內；中央主樓梯可依上一節的選取步驟進入逐層工具。
2. 在「編輯梯段」選擇要調整的樓層區間，也可以用旁邊的前後箭頭切換。檢視切片以該段較低的樓層為準，例如編輯 8F → 9F，就看 8F 的切片。
3. 拖曳畫面上的「✥ 移動此層樓梯」，只平移目前梯段；每層可有自己的平面位置。
4. 展開「微調形狀」，拖金色控制點調整本段轉角，或按「直梯／L 形／U 形」改變本段形狀。不需要填寫座標或尺寸欄位。

底部樓層選單可前往空樓層查看樓梯。切換檢視樓層只改變畫面；拖曳、切換梯段形狀與「逐層設定樓梯」才會修改配置。空樓層的可編輯梯段是沙盒設計功能，不代表原文新增了房間、入口或可遊玩區域。

逐層設定、單段移動與單段形狀修改都會保存，並納入共同的復原／重做紀錄；匯出 JSON 時會一併保存各梯段配置。仍可用 `Esc` 取消尚未完成的拖曳。編輯後請檢查相鄰梯段的接點、平台與房間門口。

### 跨層連接

先在起點樓層點選路口，再用底部樓層切換控制前往目標樓層，最後點選目標房間。切換檢視樓層會保留尚未完成的起點與轉折；兩端有高度差時自動產生樓梯；跨樓層的新連線會直接建立逐層梯段。

底部「檢視樓層」只改變正在看的樓層；選取房間的上移／下移一層按鈕會真正更改房間配置。樓層高度壓縮與展開也僅供檢視。

### 修改現有道路

直接點選道路或樓梯，顯示它的控制標記：

- 拖曳轉折點，改變路徑形狀。
- 拖曳門口端點，沿牆調整位置，或改接其他房間。
- 使用路段中間的新增控制點標記，加入並調整轉折。

選取一般通路後，也可以直接按右側「直連／L 形／U 形」切換路線，或按「刪除通路」。已逐層設定的樓梯使用「編輯梯段」下方的「直梯／L 形／U 形」，作用於目前選取的梯段。

完成拖曳或直接操作就會保存，無需按「套用通路」。平面道路只沿 X／Z 軸前進，以直角轉彎；樓梯的高度沿路段上升或下降，轉彎處配置平台。

## 進階設定與檢視

左側「單層檢視」會同時顯示該層房間及途經的上下樓梯，包括地下層與無房間樓層。這是預設檢視行為；切換樓層只改變顯示範圍，不修改樓梯配置。要直接調整房間、道路與樓梯時，開啟「編輯模式」；要逐層放置或微調形狀，可在連接工具中切換「移動」並選取樓梯。

需要精確數值時再展開進階設定：房間名稱、尺寸、位置與局部高差，以及通路寬度、單雙向、門口牆面、L 形／U 形樓梯、斜坡與各折點高度。進階欄位修改依面板的「套用修改」或「套用通路」按鈕保存；一般滑鼠操作不需要開啟這些表單。

離開編輯後可拖曳旋轉、滾輪縮放、右鍵平移；用「立體／正面／俯視」檢查空間，「透視」切換近大遠小效果。點 P／R 編號可查看故事原文與連線條件；上一間／下一間是編號導覽，不是強制通行路線。

自動路徑會嘗試沿端點房間外側繞行。過陡梯段、垂直落差或穿房警示出現時，調整路口、轉折或樓梯形狀；這些輔助檢查不等於完成全棟避障與碰撞驗收。

## 復原

房間、道路、樓梯與拆除操作共用「復原／重做」，依完成順序保留最多 50 步。「還原初始配置」恢復隨附房間與原始 30 條連線，還原本身也能復原。重新開啟頁面後保留配置，不保留這段操作歷史。

模型操作中的快捷鍵：

- `Esc`：取消尚未完成的樓梯放置、畫路或拖曳，不寫入修改。
- `R`：在樓梯放置預覽中旋轉 90°。
- `Ctrl+Z`／`⌘Z`：復原；加按 `Shift` 可重做。
- `Delete`：刪除目前選取的通路。

輸入欄位與匯入／匯出視窗開啟時，這些模型快捷鍵不會接管文字編輯。

## 保存、匯出與匯入

完成滑鼠操作或套用進階修改後，會自動保存至目前瀏覽器，也可以按「儲存配置」再次保存。正在繪製、尚未接到終點的路線不屬於已保存配置；請留意操作狀態訊息。

1. 在左側「場景檔案」按「匯出場景檔」，直接下載 `dead-signal-scene-YYYYMMDD-HHmmss.json`。檔名包含匯出日期與時間，方便保留不同版本。
2. 之後開啟這份模型的 `editor.html`，按「載入場景檔」，選取先前保存的 `.json`，選好就會載入。
3. 開啟「編輯模式」繼續修改，或使用「連接樓梯 A → B」接路。若載錯版本，按「復原」即可撤回這次載入。

場景 JSON 保存全部已完成的配置：房間名稱、位置、樓層、尺寸與局部高差，完整道路連線、路口、方向、形狀與折點，以及各層樓梯。地下樓梯與 43F 出口通路也包含在內。尚未點下的樓梯放置預覽、尚未完成的畫路與未套用欄位不會被保存。

JSON 是場景資料；要重新觀看與編輯，需開啟本模型的 `editor.html` 再載入。移到另一台電腦時，請同時保留模型資料夾與 JSON 備份。

- 下載受阻時，可由「連接樓梯 A → B → 進階設定」按「匯出場景 JSON」，在視窗按「下載 JSON」或「複製 JSON」，把內容另存為 `.json`。
- 也可以按「載入場景 JSON」，選擇檔案或貼上完整 JSON，再按「載入場景」。
- 本版匯出版本 3 配置 JSON，包含新增房間；也相容舊版版本 1／版本 2 配置 JSON。載入舊檔會完整恢復該檔內容，移除當前新增的房間，整次載入可以復原。版本 1 只有房間配置，載入時會套用房間並恢復原始 30 條連線與預設出口通路；不會沿用載入前的自訂通路。版本 2 保留其通路配置；舊檔缺少出口資料時使用預設出口。
- 載入前會驗證整份資料；有無效房間、重複通路代號或超出範圍的路線資料時，不會先寫入其中一部分。整次載入可以復原。

本機儲存依瀏覽器與開啟位置而定。同一網站來源下，原 `index.html` 的存檔可由 `editor.html` 讀取；本機檔案網址、更換瀏覽器、改用其他來源或清除瀏覽器資料後，不一定能讀到先前保存的配置。請以匯出 JSON 作為可攜備份；本機保存不會直接覆寫 `editor.html`，也不會自動修改原始碼。

本版使用本機儲存鍵 `dead-signal-building-sandbox-v2`；若尚無新版配置，啟動時會嘗試讀取舊版 `dead-signal-building-layout-v1`，把原有房間編輯遷移到新版。兩者皆只在相同瀏覽器與相同來源位置下可讀取。

## 編輯範圍

保留原有 26 個 P／R 節點，可自由改名、移動、改樓層與尺寸；可新增自訂房間，整棟最多 200 個房間。新增房間可用復原撤回，原故事房間代號不可刪除。房間通路可新增、改接、刪除，總數上限 160 條；端點必須是兩個不同的既有房間。A → B 平台連線另存於 platformLinks，上限 160 條，至少一端為既有樓梯的平台。

沙盒可改變原圖的相鄰關係或通行方向，這些會作為自訂配置保存。初始故事連線與自訂路線需分別看待；不要把自己新增的捷徑解讀為原文既有動線。編輯後仍需目視檢查房間交疊、通路轉折、樓梯平台與端點銜接。

正式樓層定位、原始房間用途與故事說明仍可在右側查看。使用者可另提配置，但編輯值不會變成故事原設定；例如把 R17 移到其他樓層，原文明定的 32F 仍是原文依據。

## 原始碼與驗證

`spatial.js` 管理初始配置、逐條通路與理由；`story-props.js` 管理家具、玻璃和地標；`model-source.js` 管理 Three.js 與操作；`room-create-3d.js` 管理滑鼠拖曳建立房間；`editor-state.js` 管理房間與通路資料、版本相容、格式驗證和復原／重做；`sandbox-routes.js` 管理路口與直角路線幾何；`sandbox-ui.js` 管理進階道路編輯面板；`mouse-editor.js` 管理直接拖曳、畫路與拆除；`mouse-routes.js` 將滑鼠路徑轉成可保存的通路與編輯控制點；`floor-stairs.js` 管理逐層梯段、獨立位移、形狀與平台高度；`data.js`／`scene-data.json` 的節點目標、通行條件與規格連結，由儲存庫根目錄的 `node tools/sync-canonical.mjs` 依正式劇本同步。房間配置與編輯器資料格式不隨敘事同步改寫；同步後執行 `npm run build` 更新嵌入資料。

修改時執行 `npm install`，編輯後執行 `npm run build`。僅查看現成 HTML 不必安裝。

原始配置的節點、連線、相鄰關係與故事空間檢查，只適用於隨附布局。任意編輯後的布局仍需重新檢查；保持直角轉折不代表路線一定沒有穿房或樓梯坡度一定合適。

此為故事空間灰盒與配置編輯器，不模擬遊戲解鎖或遊戲進度存檔；正式關卡仍需驗收鏡位、碰撞、導航與門禁。
