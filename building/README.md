# 灰燈寨 · 上部故事空間模型 / 第二版

使用 Chrome、Edge 等支援 WebGL 的瀏覽器開啟 `index.html`。Three.js 與資料已內嵌，可以離線使用。

## 故事空間修正

- 地下 P0、P1、P2 以短管線通道相接；P2 處理室暫靠 B3，出口爬梯跨越 B2、B1。原文只指定 B3–B1 上行段，沒有固定 P2 為 B1。
- R1 櫃檯後是 R2 舊麵店後廚，紅鐵梯從後廚梯口直接上接 R3 側門，不繞建築外緣或返回 R1。R3 宿舍、R4 洗衣廁所及 R5 工坊同層相鄰；R4b 是 R4 內的梯下神壇，不另造房間。
- R6–R11 沿住宅長巷與內井構成產線。R7 窄橋接 R8；R9 比 R8 低兩級，R10 是祈禱平台，R11 為錯層第三排工位。沒有新增 R7→R11 或 R8→R11 直連。
- R12–R16 構成修理、診療、貨梯與設備後勤群。R15 機房與 R16 伺服器室貼鄰，以短梯／防火門銜接，再從冷卻管下的維修夾層上行至 R17。
- R18 改為狹長消音走廊。R19 與 R20 共用同一片實體單向玻璃，由側門繞至墊高的觀察側，再往 R21。R22 保留釋放平台、下折避梁與向 43F 上行出口。
- 跨幕樓梯放在建築內的維修脊柱；R17→R14 誤導回路仍獨立保留。共用貨梯只呈現轉接井道，不新增乘梯跳層通路。

## 原文與配置提案

來源：[灰燈寨企劃庫](https://hanksonwu-design.github.io/dead-signal-docs/)，2026-09-23 讀取的節點圖與逐房規格。

直接沿用原文：26 個上部節點、30 條連線、方向、雙向條件、门禁／回訪規則、高度帶、房間用途與相鄰空間描述，以及 R17 的 32F。

本次提案：帶內具體落層、尺寸、方位、梯井位置、高差數值、內井封蓋標高與示意家具。原文沒有完整尺寸圖，這些不能當成已定案的建築圖。

| 原文高度帶 | 第二版落層提案 |
|---|---|
| B3–B1 | P0／P1 在 B3，P2 處理室暫靠 B3；出口梯經 B2、B1 |
| 1F | R1、R2 |
| 2F–7F | R3、R4、R4b、R5 暫以 2F 為共同基準 |
| 15F–20F | R6–R11 暫以 15F 為基準，使用局部門檻與錯層 |
| 28F–31F | R12–R16 暫在 31F 後勤平台；機房／伺服器局部墊高 |
| 32F | R17，原文明訂 |
| 41F–42F | R18–R21 以 41F 為基準，觀察工作側墊高；R22 在 42F |
| 43F | 分部門檻，未建立下部 R23 房間 |

3F、5F、8F–14F、21F–27F、33F–40F 封閉區未配置可走房間。整體關卡向上推進，房號增加不代表升一層；故事要求的局部下階與誤導回返保留。

## 操作

- 拖曳旋轉、滾輪縮放、右鍵平移。
- 左側選區域或單層；俯視看平面，立體看高差。
- 點選 P／R 編號，右側查看故事配置理由、原文依據、入口出口及條件。
- 原始規格連結直接定位「空間與畫面製作定位」。
- 區域／單層模式只顯示區內通路，跨區連接請看全棟；右側仍列全部連線。
- 樓層展開與高度壓縮僅方便閱讀，不代表真實楼高。上一間／下一間是編號導覽，不是強制行走路線。

## 原始碼與驗證

`spatial.js` 管理配置、逐條通路與理由；`story-props.js` 管理家具、玻璃和地標；`model-source.js` 管理 Three.js 與操作；`data.js`／`scene-data.json` 包含原圖與逐房原文快照。

修改時執行 `npm install`，編輯後執行 `npm run build`。僅查看現成 HTML 不必安裝。

已驗證原圖節點／連線一致、可達性、封閉樓層排除、住宅工坊同層、機房伺服器相鄰、共用玻璃，以及壓縮／等距兩種模式下通路中心線不穿過無關房間。此為故事空間灰盒，不模擬解鎖或存檔；正式關卡仍需驗收鏡位、碰撞、導航與門禁。
