# 遊戲劇本與製作規格拆分後：一致性與邏輯複查

日期：2026-10-01。此為本次檢查紀錄，不取代劇本或製作規格；較早的 reviews 紀錄保留為歷史。

## 結論與範圍

以八份遊戲劇本、八份製作規格、總目錄與共用附錄為正式來源，交叉核對分類文件、精簡版小說、場景道具總表、場景圖與網站閱讀入口。本次發現並修正的問題，主要是舊摘要、來源位置、觸發時點及存檔邊界不一致，沒有改寫主線走向、增設必要線索或新增房間。

修正後，在本次檢查範圍內未再發現會阻斷既定主線的文件矛盾。這是文件、資料與網站驗證，不是 Godot 實機通關證明，也不能據此宣稱全案已無任何邏輯問題或已完成製作。

## 主線邏輯複核

| 區段 | 複核重點與保留邊界 |
| --- | --- |
| 序幕至第一幕 | 受控接收不等於自願；被騙／被擄由實讀來源支持。K0 是辨路索引，不是實體鑰匙；不提前完成正式推理鎖定。 |
| 第二幕 | R11 依 R8 真實讀卡結果與實際取得、解讀的證據查驗；不讓選填支線變成必要門票，也不憑空產生聲音來源。 |
| 第三幕 | 三種供電路線都保留必要主線；選填資料的損失與確認分開。R17 使用當地來源及已存觀察，不要求回到封閉樓層補收。 |
| 第四幕 | E3-01／02／03 支持第三層鎖定及恐慌轉折；只停用校正區指定環境來源，不推成此後所有遭遇均失效。 |
| 第五幕 | 文件倒填、七分鐘空窗及「曾受害／後來加害」分開成立；七分鐘不是全樓斷電，也不抵銷主角責任。R23 看見臉與姓名，不等於已完成 R31 的本人核驗。 |
| 第六幕 | R29 範本比對可略過；既有核准選擇與主線門檻分開。R30 不可逆操作維持預先確認；R31 依原件、權限及本地供電核驗，不憑空補全身分。 |
| 終幕 | 先揭露、再防禦、後選擇；不可逆提交、放行結果、人物後果與片尾名冊分階段。D 留下且不解封，E 的抹除不擴張成刪除全世界證據。 |
| 通路與文化 | 七段過渡不新增房間或主線門檻；文化近看維持選填。機關階段與通路演出進度分開，不能用看過過場取代實際操作。 |

上述複核保留原有揭露順序、主觀觀察與客觀資料的區別，不因製作端知道真相而預先給玩家答案。
